## Operational notes

Initial real Docker validation used the working-tree entrypoint mounted into
the existing local image. After the requested rebuild on 21 September,
`agent-runtime:latest` is image `f61d6903bb86`. The full dependency rebuild was
stopped because package downloads were slow; the runtime layer was rebuilt from the prior
image with `COPY --chmod=0755 entrypoint.sh /usr/local/bin/entrypoint.sh`, keeping
its installed dependencies. The prior image is retained as
`agent-runtime:pre-p1-20260921` (`7c09ee9be3ae`).

The baked entrypoint SHA-256 matches the source. Smoke tests against the image's
default entrypoint passed with `--network none`: UID 1001 can edit and create
snapshot files; host contents, owners and modes remain unchanged; a read-only
bind workspace starts successfully. No model API requests were made. The
validated `bin/airun` was also installed at `~/.local/bin/airun`, with a backup
of the previous binary retained in the system temporary directory. No proxy
was deployed or restarted.

New records have a bcrypt hash plus a lookup fingerprint of the random token.
Old bcrypt records without fingerprints need bounded retries (`429` with
`Retry-After: 1`) for their first login; successful authentication saves the
index. Authentication admission is 600 attempts/minute, four concurrent checks,
and one concurrent legacy scan. Legacy retry state expires after one minute
and is bounded to 128 credentials. File errors fail closed; external revoke and
restore are observed before authentication without SIGHUP.

Old connect installations with only `_airunManaged: true` have no original
values to recover. Disconnect preserves these files instead of deleting or
guessing their prior configuration. Current Go, Bash, and PowerShell clients
use a shared `_airunBackup` schema for reversible changes.
